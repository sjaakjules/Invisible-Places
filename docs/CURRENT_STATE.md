# Current State Reference

This document describes the implemented project surface for future edits. Evidence logs live in `docs/logs/`.

## Point-Cloud Rendering

- Supported point-cloud renderer modes are Beauty and Fast Basic.
- Raycast/Raytracing is not part of the active renderer, export, shader, CMake, settings, serialization, or test surface.
- Project files that contain `"point_cloud_renderer_mode": "raytraced"` load as Beauty and save back as `"beauty"`.
- Beauty rendering keeps the unified material path for advanced point styling. Fast Basic keeps cheap colour and point-size controls for preview-oriented rendering.
- Role-named sibling PLY files are grouped as one scene in the UI. Complete ROCK/SAND/VEG sets at one quantized spacing are exposed through the scene-wide **Visible Point Cloud** selector; incomplete and ambiguous sets are unavailable.
- Folder-level point visuals are edited once and mirrored to the committed scene roles. Values remain authored against 1 mm spacing, while render-only footprint and measured-count coverage compensation keep sparser display bundles visually comparable without changing the UI values.
- Canonical ROCK/VEG 1 mm and SAND 2 mm sources load on demand for explicit Bake Path and legacy Ripple/Field recalculation. They are not a startup prerequisite. Only the committed display bundle is renderable/GPU-resident; staged targets switch atomically and never enter viewport or export snapshots.
- Scalar-field bindings resolve by exact name, then one unique case-insensitive name. Missing named fields retain their binding and render its constant fallback instead of silently using the same numeric slot from another density variant.
- Roughness surface motion is role-gated to VEG in grouped scenes. ROCK and SAND remain stationary for that effect.
- Shader shoreline waves are role-gated to SAND in grouped scenes. `Foam Fronts (Current)` preserves the existing `SandCloudShorelineWaveValue` path; `Bay Waves` is the continuous, always-populated to-and-fro alternative; and `Height Foam` adds independent run-up/break heights, persistent offshore foam, stronger incoming gathers, and fading returns. Shoreline is an ordered list of up to five Water-owned effects backed by explicitly named profiles; no Default or generated preset is authored. Editing a base on an object upserts `<base>_<object name>`, while reselecting and editing the base overwrites that same object copy. Saved Visual profiles carry no Shoreline state. None of the algorithms allocates region memberships or dense scalar fields.
- Scene3 scanner-patch validation renders saved cameras Patch 01-04 from the full 1 mm bundle with exact `Projector-01` bindings, a fixed 2 mm world-space point diameter, and every Shoreline path disabled. Patch 04 is the unannotated ScanID 9 ROCK density-edge view; its installed augmentation is append-only ScanID 13 data, leaving existing ScanID 0-9 bytes intact.

## Water Workflow

- The Water panel exposes Ripples, Shoreline, Seepage, Rain, Flow, Mesh Flow, and Field in that order.
- Basin and Runoff records in older project or water-source JSON load harmlessly and do not participate in active UI, runtime editing, or new saves.
- Older Caustics region records load into Ripple layers using the Caustic Lace overlay type.
- New project and water-source saves use v2 water keys and omit `water_basin_regions`, `water_runoff_regions`, and `water_caustic_regions`.
- Flow, Mesh Flow, and Field streams are derived render output. Rain uses a dedicated GPU particle draw backed by the shared surface cache and does not create a generated point-cloud session. Mesh Flow likewise uses one fixed 4,096-particle, 24-history GPU allocation over the resident Ground table; it no longer warms a triangle `MeshSurfaceCache`, builds a generated CPU cloud, or exposes authored Mesh sources/capacity controls. Ripple effect data is evaluated on the active/base cloud through sparse runtime memberships and compact procedural params; Shoreline waves are evaluated during the SAND point-cloud draw. Seepage is evaluated on eligible base-cloud points through retained compact topology/hash plus frame-safe parameter buffers and does not create a generated point-cloud session. Stale legacy `-Ripples.generated` sessions are cleared rather than refreshed. Normal project layer persistence skips generated water output, and v2 settings plus cache/style data regenerate the needed in-memory output.
- Flow point sources and manual spline sources are project-owned state, not separate global saved state. A new project can therefore start with no sources while retaining reusable path, lane, trail, rain visual, and visual defaults.
- Seepage nodes are placed or moved from visible-scene depth and the resident 10 mm shared cache, without loading canonical analysis clouds, and default to ROCK and VEG roles. Grouped scenes snap to connected authored cache surfels, trace a maximum-downhill centreline, and flood only same-surface cells at or below the node within explicit selection limits. VEG support is associated with the connected ROCK substrate and SAND remains opt-in; disconnected/background surfaces and generated Flow are rejected. The renderer performs one sparse cache-cell lookup per point rather than scanning a visible cloud. Node points remain visible in the viewport; the transient Show Structure Overlay reports the selected cache-cell footprint and connectivity without affecting renders or exports. New projects use restrained Chaotic Bloom; saved looks without a pattern also load as Chaotic Bloom.

## Water v2 Behavior

- Ripple contributes to active/base point-cloud visual evaluation through sparse GPU/offline runtime memberships and params. Shoreline contributes through SAND-role point-style shader uniforms. Field Surface Motion currently contributes through composable `water_effect_*` scalar fields.
- Seepage builds bounded connected support from the shared cache. Each support cell stores packed downstream/lateral metrics, normal, role, confidence, and flags, with at most 262,144 references per node and eight node references per cell. Placement, role, selection-limit, depth/edge, or cache-identity edits rebuild only that node asynchronously and retain its last settled output on failure. Live reach, width, prominence, strength, visibility, scenario, per-node animation, wetting, and Rain edits retain topology/descriptors and update only compact frame-ringed parameters. Auto quality resolves from effective point invocations, while explicit Low, Balanced, and High modes remain available.
- Continuous triangle-mesh routing is not part of the current Seepage runtime. Connected authored cache cells provide topology without uploading or querying mesh data in the Seepage shaders.
- Seepage supports Wet Rock Sheen, Chaotic Bloom, Wetting Trickle, and Contour Pulses. Wet Rock uses seed-rotated world-space 3D gradient noise, analytic micro-normal variation, the real camera vector, and a virtual environment direction for damp patches and angle-dependent reflection. Chaotic Bloom domain-warps ridged 3D noise along the connected downhill metric for irregular evolution. Wetting Trickle blooms small saturated patches, advances a soft irregular front over downstream distance, and leaves short narrow downhill fingers with persistent damp sheen. Contour Pulses composes authored launches into a compact static reference field only when shape settings change, then advances one to three quality-scaled phase samples from renderer time on the GPU; clock-only frames require neither CPU field construction nor Seepage parameter publication. The stationary surface field shapes their edges while nearby-speed phases catch and overlap. CPU/offline evaluation uses the same sampler and explicit output time. Common wetness, coverage, glisten, Rain Response, blend, tint, opacity, emission, and point-size controls remain shared. The panel shows only controls used by the selected pattern and gives every parameter-name label a hover tooltip.
- Project scenarios globally override node looks while retaining each node's geometry, seed, roles, authored strength, and enablement. The seeded Past/Future (formerly Pre-Colonisation Wet) and Current (formerly Contemporary Managed) scenarios intentionally share pattern coordinates but differ in level, spread, wetness, coverage, glisten, evolution, and Rain Response. Authored Node Looks restores the profile/local-look hierarchy.
- Animation schema 22 stores normalized global water scenario keys with complete look snapshots, Seepage level/spread, continuous Rain and Flow levels, Mesh Flow level/Rain gain/persistence/rise/recession, Seepage Rain delay/rise/recession, outgoing Smooth/Linear/Hold interpolation, and embedded linked-scenario fallbacks. Each track can also store normalized per-node Activity, Local Spread, Wetting Front, Reach Scale, Width Scale, and Prominence keys by stable node ID. Animation-v10 `localSpread` remains readable; missing new factors default to one. Schema 15 introduced reversible paired endpoint smoothing, schema 16 added rebuildable linked-loop source/phase/padding metadata, schema 17 added elapsed-time overlap bounds plus the original camera/focus poses for every user-enabled smoothing key, schema 18 recorded full-frame versus directional horizontal cross-wipe alignment, schema 19 replaces paired loop smoothing and linked-loop metadata with velocity-blend links plus localized key corrections (schema ≤18 shapes migrate on load), schema 20 adds the animation's default live-view window size, schema 21 stores per-key spatial-spline parameter weights and materialized endpoint tangents so evaluated-key insertion cannot reshape the curve, and schema 22 adds explicit localized-correction tangents plus a deprecated duration marker used only to migrate initial reciprocal-extension files. The UI displays and edits key time in seconds while storage remains normalized. A reciprocal terminal extension rescales normalized timing/water/effect positions so every existing event remains at its original absolute frame. Camera position selects those keyed values only; procedural effects continue from steady elapsed time in live view, even while paused, and from deterministic full output time in export.
- Scenario and look animation changes compact parameter buffers only. Each live or export sample resolves one immutable `WaterFrameState` containing normalized/sample time, the raw scenario, the Seepage-delayed scenario, the independently filtered Mesh Flow moisture value, and per-node states. Rain and ordinary Flow consume the raw state; Seepage uses its deterministic 120 Hz Delay/Rise/Recession moisture envelope, while Mesh Flow uses its own deterministic 120 Hz Rain rise/recession/persistence envelope. Visible Rain is not delayed and out-of-order scrubbing remains reproducible. Keyed Flow continuously fades and shapes the complete settled trail population without seed-threshold switching or phase changes; keyed Mesh Flow changes active fixed-capacity particles and appearance without reallocating its Ground table, history, Rain-seed ring, or contact-event buffers. A long Rain/Flow/Seepage/Mesh Flow animation therefore does not rebuild connected Seepage support, rebuild Flow geometry, warm a triangle cache, dispatch CPU route generation, or upload point-cloud/shared-cache data.
- The region `Shoreline` Ripple overlay remains separate from Water > Shoreline. Region Shoreline uses the Ripple tide-band runtime path inside selected polygons; Water > Shoreline uses the SAND point cloud to simulate waves at the beach boundary without rebuilding Ripple memberships.
- Ripple pattern and contribution edits can live-update compact runtime params when region membership is current, giving millisecond-scale feedback and avoiding dense full-cloud scalar uploads.
- Water effect composition supports intensity, emission, opacity add/multiply, point-size add/multiply, and colourise contributions with add, max, multiply, screen, and override blend modes.
- Existing base-cloud scalar mappings, including Height and Intensity driven mappings, remain active while water effects compose on top.
- Ripple and Field regions use the authored clicked polygon boundary for containment, so concave regions preserve their cut-out areas.
- Ripple and Field share one region-selection path that exposes selected base point indices, edge weights, normals, scalar values, field vectors, and manual control flags.
- Flow path cache reuse, hidden branch IDs, smoothing refresh, support-layer signatures, and baked path anchors are part of the saved/reloaded water workflow. Schema-45 project saves externalize clean generated branches to immutable, complete-payload-checksum-addressed scene-local `.invisible_places/cache/flow/*.flowpathcache` sidecars (project-local fallback) and keep only a validated manifest in JSON; stale caches are omitted. Explicit Bake Path and settled project Save may write the sidecar, while live Lane/Trail/style edits remain in memory. A sidecar is loaded only through its checksum-bearing project manifest, so projects sharing terrain/settings cannot exchange hidden-branch state. Bake Path reuses branch-level emitter fingerprints so moved, added, or deleted sources rebuild independently when the support signature still matches, then queues source-local Lane/Trail work. Global **Show All Flow Trails** and per-point/path **Show Trail** flags compose as visibility parameters and never invalidate these routes; **Generate Trail Geometry** remains the separate Advanced topology control.
- Manual Flow path sources bypass downhill path generation. Live GPU generation evaluates their open centripetal Catmull-Rom control points directly; deterministic CPU/offline sampling still produces lane-ready anchors with rotation-minimizing frames and the identical 31-field Trail scalar contract. Every control node can inherit the Lane profile cover, use an absolute metre value, or multiply the global cover (for example `0.2` or `2.3`); a bounded smoothstep envelope interpolates the resolved cover along the same 3D spline on CPU and GPU. Optional Surface Guide keeps endpoints and first-to-last direction fixed while the shared 3D surface tier bends the interior within that local Lane Cover Width, projects gravity onto the selected surface sheet, bunches weak/rough support, and falls back to the authored frame when support is missing. Lane assignment fills authored lanes deterministically from the centre outward, including manual routes without generated-path analysis. Generated point-source routes also receive centripetal Catmull-Rom presentation interpolation after profile smoothing while cached raw branches remain unchanged. Generated and manual sources can coexist; Bake Path only rebuilds point-source branches.
- Flow source Path/Lane/Trail selectors have persistent per-assignment locks. Unlocked sources preview matching unsaved profile edits and fall back to the saved profile when no edit exists; locked sources always resolve the saved copy. Manual path sources use the same rule for Lane and Trail.
- Add Path Source opens a transactional viewport draft. Ctrl+left-click adds surface-snapped nodes, a node click selects it, Delete/Backspace removes it, and double-clicking the curve inserts a node in curve order. The selected-node gizmo moves on world X/Y/Z arrows, XY/XZ/YZ squares, or the center's camera-facing plane. Save requires two distinct nodes and refreshes derived trails; Cancel restores the committed source and output. Empty-space navigation and double-click pivot behavior remain available. Show Source Nodes / Paths hides point-source markers and committed authored-path guides for an unobstructed trail view, while an active path draft remains visible.
- Every point and manual Flow source owns Maximum Flow Strength and Rain Response. Effective activity is `clamp(maximumFlowStrength * (flowLevel + (1 - flowLevel) * rainLevel * rainResponse), 0, 1)`; defaults are 1 and 0 respectively. The Flow Level/Flow Off controls are part of the same scenario key as Rain and Seepage.
- Ordinary Flow Lane/Trail topology is GPU-native and source-local. `UploadWaterFlowGpuSource` uploads only sampled point-source anchors or manual Catmull-Rom control points plus one settings record, then runs route and Trail compute passes against the resident shared surface table. Each source owns geometrically growing output capacity and the existing field-major 31-slot Trail scalar layout (`trail_role`, `trail_id`, `source_id`, and the remaining route/Trail fields). One result remains active while a new revision computes; live edits replace the single queued request with the newest revision, stale work is discarded, completed buffers promote after their fence, and prior outputs retire only after referring frame fences. Deletion similarly releases only that source after compute/frame safety. Appearance, source activity, Rain response, opacity, width, speed, and visible length update style state without topology dispatch. Deterministic CPU builders remain for offline/fallback snapshots, and Hiding a Path View branch still affects only its owning source. Per-source diagnostics expose requested/completed revisions, surface-upload revision, transferred bytes, dispatch count, capacity, active samples, pending state, and Surface Guide use.
- Flow Path has an optional viewport-placed attractor. Its strength biases XY candidate ranking toward the attractor, while Z remains the vertical descent axis and attractor edits correctly dirty the path cache.
- Grouped ROCK/SAND/VEG scenes build combined Flow/Field analysis support only from CPU-ready canonical analysis sources, not from the selected display bundle. Separately, one shared `WaterSurfaceCache` streams every file in the exact complete 2 mm bundle once, or the nearest complete fallback bundle, and deterministically quantizes it into 10 mm Rain ROCK/SAND XY, VEG 3D, and orientation-independent authored-role support. It resolves the explicitly active scene's unambiguous 5 mm `MESHSampled` point cloud and reduces its upper, vegetation-supported surface to a separate 10 mm Ground XY tier; ambiguous scene-local Ground candidates are rejected. ROCK/SAND retain the exact maximum height per XY cell, Ground retains its highest occupied cell, and all normals are hemisphere-aligned before averaging. The Ground tier stores downhill direction, convergence/confidence, connected-component identity, eight-neighbour connectivity, and a compact vegetation-supported highest-+X entry table without reclassifying it as Rain or Seepage terrain. None of these sources load as display or canonical analysis clouds. Display switching therefore leaves support signatures, connected Seepage topology, Ground routing, path/field caches, source placement, Rain collision, Flow guidance, and region analysis unchanged.
- Shared surface-cache schema 4 (`IPWSC004`, algorithm `water-surface-10mm-normal-average-ground-v4`) persists aggregate records, the 32-byte Ground GPU hash table, the other power-of-two GPU hash tables, and a streaming payload checksum at `<scene>/.invisible_places/cache/water/<signature>.surfacecache`, with project-local hidden fallback and a 5 GiB persistence ceiling. Schema-3 `.surfacecache` and schema-2 `.raincache` files remain legacy-readable; their algorithm/schema identity makes them stale when Ground is required. Runtime code uses the neutral `WaterSurfaceCache`/`WaterSurfaceSource`, `Build`/`Save`/`UploadWaterSurfaceCache`, `WaterSurfaceFlowView`, `WaterGroundFlowView`, and `WaterSurfaceUploadRevision` API. The active scene warms only after its display upload completes; a valid disk cache loads sequentially without rescanning point clouds, rebuilding hashes, or hashing the full payload twice. One reusable staging allocation capped at 64 MiB copies immutable tables into device-local memory, then preprocessing runs once. CPU GPU-table vectors are released after installation.
- Point-cloud loads and shared-surface build/load plus GPU preprocessing share one exclusive high-memory slot. After the visible display commits, the shared surface cache gets the slot before inactive queued loads; there is no separate dynamic-mesh warmup.
- Each scene manifest records source fingerprint, sidecar path/size/checksum, and requested/built rebuild generations. Runtime derives Missing/Stale/Building/Valid/Failed status from that manifest and the current install. **Rebuild Cache** increments the requested generation and keeps the last settled GPU cache active until a clean replacement is uploaded; Valid is reached only after preprocessing, and a failed build waits for another explicit request rather than retrying every frame.
- Ripple memberships and analysis-based Field presentation are never allowed to reuse point indices across density variants. A display switch itself performs no analysis scan or topology rebuild; missing display-specific derived state remains dirty until an explicit recalculation.
- Flow Lanes animate Trail points from Trail age, seed, speed, wetness, confidence, width, and render time. Playback changes do not require topology regeneration; the existing ordered `trail_*`/route scalar names remain the renderer contract.
- Field supports user-defined Surface Motion, No Flow, Bridge Allowed, and Bridge Blocked regions.
- Region-built Field vector caches are saved under `Saved/water/<source-stem>-WaterFieldCache.bin` and reused when support, settings, and region fingerprints match. Path-anchor Field caches are currently rebuilt from Flow path anchors and kept in memory.
- Flow trails, GPU Mesh Flow samples, and Field Streamlines share the animated 31-field Trail render schema. Flow follows path anchors through Lane profiles and Field follows cached vector-field integration from perturbed source points. Mesh Flow writes its fixed 24-sample GPU history directly into that render contract while 4,096 persistent particles advance over the active scene's owned Ground table. Dry emergence uses only vegetation-supported cells within `max(0.75 m, 4% of component X extent)` of each connected component's highest-+X edge and favours convergence. VEG Rain collisions first keep their leaf-to-leaf response, then write a fixed 1,024-entry GPU seed ring that can produce distributed Ground trickles after the propagation delay; ordinary Flow sources contribute zero Mesh Flow seeds. Per-particle noise gives individual trickles while a lower-frequency shared wind term moves the population coherently. Trails stay surface-bound until a terrain-contact cell, where they fade and enqueue bounded ROCK/VEG contact responses. No equivalent CPU Mesh Flow cloud is generated. Rain remains isolated in its own compute and six-vertex streak pipelines.
- Rain collision uses the embedded shared-cache view: sparse ROCK/SAND XY top-surface cells plus VEG 3D occupancy voxels. A bounded 10 mm look-ahead trace chooses the earliest role hit for wind-slanted drops and supplies the averaged surface normal. Approaching droplets decelerate and morph into surface-tangent ellipses while retaining unslowed impact energy. Static parameter-only controls tune the approach, deterministic broken ROCK edges/falloff/persistence, and visible descending VEG crowns, hops, and twinkles; collision still stops and deterministically respawns the particle.
- GPU Rain smoke coverage uses the approximately 2.1 million-point SampleScene and 14.8 million-point Scene3 5 mm display bundles. `rain-gpu-sample-scene` and `rain-gpu-scene3-5mm` assert that live weather/visual/effect edits and GPU EXR comparisons reuse one shared-surface upload. Cross-feature startup/edit/export coverage uses `water-integration-sample-scene` with its lightweight project plus the tracked animation fixture under `tests/fixtures`, and the separately labelled full-site `water-integration-scene3-exhibition` with `Saved/ExhibitionFinal_project.json`/`Exhibition`.
- Field streamlines stay surface-bound, split rejected gaps, fade low-confidence support when configured, and report accepted bridge, rejected gap, fade, termination, and manual control diagnostics.
- Viewport and raster export include sparse Ripple runtime effects, SAND Shoreline waves, all four compact-grid Seepage patterns with matching per-node/Rain timing and camera reflection, Flow trails, GPU Mesh Flow trails/contact responses, dedicated GPU Rain plus role-aware impacts, and active-cloud Field Surface Motion without requiring water PLY export. Screen Sprites, World Surfels, Fast Basic, viewport EXR, still, and animation/video paths consume the same immutable per-sample `WaterFrameState`, including the independently filtered Seepage and Mesh Flow moisture values.
- Field Surface Motion is a candidate for the same optimization pattern as Ripples: region-bounded support, shader/offline procedural evaluation, and parameter-only updates instead of dense base-cloud field uploads when only visual settings change.

## Serialization

- Project serialization uses schema version 73 for the current project shape; standalone water-source documents use schema version 27. Animation-path saves use schema version 22, nested Rain settings remain version 3, and the shared binary water-surface cache uses schema version 4.
- Project schema 73 stores the preferred live-view window size and whether it is locked. Animation schema 20 stores its default live-view size; loading an animation applies it unless the project lock is enabled. Legacy animations with no size leave the current window unchanged until saved.
- `scene_point_cloud_groups` is authoritative for each grouped scene's display spacing, loaded/visible state, and per-role analysis/display paths. Legacy per-layer grouping and selected-variant fields remain compatibility mirrors.
- Schema-32-and-earlier projects preserve legacy analysis candidates and migrate to the visible primary/ROCK complete bundle when possible, otherwise the nearest complete bundle with a denser tie-break. Scenes without a complete bundle remain non-switchable `Mixed` sets.
- Project documents also persist Water v2 authored state, explicit active water-scene ownership, and compact shared-surface and Flow-path manifests. Clean generated Flow branches and branch bake fingerprints live in `.flowpathcache`; generated cache arrays are not embedded in schema-73 JSON. Mesh Flow persists automatic simulation/style settings and global scenario values for level, Rain gain, persistence scale, and Rain rise/recession; its fixed 4,096-particle/24-history allocation plus particle, seed-ring, history, and contact state remain transient GPU data. Legacy Mesh emitter, emitter-motion, attractor, and `automaticSources` fields remain readable for migration but are inactive and omitted from settled saves; legacy capacity/history inputs sanitize to the canonical fixed values.
- Nested Rain settings version 3 adds Near Surface, ROCK Impact, and Vegetation Impact tuning PODs. All rain appearance, weather, amount, and effect controls are runtime uniforms and do not invalidate or resize the collision cache and persistent GPU buffers.
- Camera shots and animation paths associate grouped point-cloud work with the scene folder, not the individual ROCK/SAND/VEG child PLY paths. Older child-path associations are canonicalized to the scene when loaded.
- Project documents also preserve water animation trail settings/profiles and caustic look settings for legacy animation and visual compatibility.
- Standalone water-source documents persist the same active Water v2 surface, including `water_manual_flow_paths`, needed to reload sources independently from projects. Manual trail overlays are derived after the active support scene loads and are never written as project layers.
- Animation paths preserve water caustic look settings for current visual style compatibility and schema-16 normalized Seepage/Rain/Flow/Mesh Flow scenario tracks, nested per-node Seepage keys, embedded scenario fallbacks, reversible endpoint-only loop smoothing, and rebuildable phase-keyed linked loops for synchronized playback and export. Linked-loop padding is anchored from each outgoing penultimate key to the incoming first key, so zero overlaps the complete terminal edge. Live Camera defaults to Overlay and can isolate A or B; the legacy blended-camera mode is absent. Overlay alternates one source render per display frame, caches both colour/depth results, motion-reprojects the cached partner from its previous camera pose to its known current pose, and composites with the linked weights. It retains one scene pass per frame while each source's actual geometry updates at half rate. Schema-10 Local Spread keys migrate with Reach Scale, Width Scale, and Prominence defaulting to one; missing Seepage Rain timing remains immediate. Older documents default Mesh Flow to level 1, Rain gain 0, persistence scale 1, and immediate Rain timing. They also default to full ordinary Flow (`flowLevel = 1`), visible global/source trails, source strength 1, Rain response 0, and disabled Surface Guide on legacy manual paths; newly authored manual paths enable Surface Guide. Existing saved looks without a pattern, and unknown or removed pattern names such as `legacy_ripples`, load as Chaotic Bloom.
- Matching-Frame Key Alignment includes **Extend Both Seams…** for target-driven fixed-lens pans whose crossed endpoints already represent the two 50%-blend poses. A source endpoint captures anchor/front/side; one destination feature-centre click generates its front/side nodes from the same physical offsets in the destination camera frame. All nodes remain re-raycastable and movable. Every stage can flip between A and B. Each selected seam span now generates both directions from that same triangle pair: a pre-roll before the source's old start and a tail after the partner's old end, with two keys per simple generated end (three for a crossed key/inflection). Signed synchronized review runs from negative pre-roll offsets through the original midpoint to positive tail offsets. Its true two-camera split keeps both triangles visible and editable, and a configurable crossfade follows the mean projected anchors plus a persistent pixel offset beyond frame. Water rendering/simulation work is suppressed while the wizard is active. A/B/Overlay Preview and atomic Apply create or update both overlaps, generated IDs, and the project link mirror under one paired save/discard dependency. Cancel restores the launch view without edits. Picking prefers a shared association but also accepts the selected or sole unambiguous pickable scene, using either CPU analysis samples or a visible committed display cloud.
- When A/B paths contain clip-plane drift captured from the live orbit camera, **Extend Both Seams…** normalizes private wizard baselines using the smallest existing near plane and largest existing far plane. **Apply Both** commits that preparation with the extensions, while Cancel discards it. The same section also offers **Normalize A/B Clip Planes** as a standalone paired `_Edited` repair whenever normalization is needed, without changing camera/focus motion, FOV, aperture, or timing.
- Generated/effect water output is treated as derived data and is not stored as normal project source layers.
